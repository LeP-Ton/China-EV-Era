# EV Era · 新能源汽车时代

一款以中国新能源汽车行业为背景的本地企业经营模拟游戏。你制定战略，虚拟高管自主执行，市场、产能、资金和历史质量决策共同决定企业的未来。

项目名：`EV-Era`；游戏名：`EV Era`；中文名：**新能源汽车时代**。

[在线游玩](https://lep-ton.github.io/EV-Era/) · [GitHub 公开仓库](https://github.com/LeP-Ton/EV-Era)

本版本实现提示词中的**第一阶段可玩 MVP**：2026—2028 年，12 个季度、156 个模拟周。不是静态界面原型，也不调用真实大模型、付费 API 或在线业务服务器。

## 开始运行

环境：Node.js 20.19+、npm。当前工作区已经安装依赖，直接执行：

```bash
npm run dev
```

打开终端输出的本地地址，默认是 `http://127.0.0.1:5173/`。首次使用填写企业、品牌、车型名称与随机种子，选择初始战略即可开始。

全新检出时先安装依赖：

```bash
npm ci --registry=https://registry.npmjs.org
npm run dev
```

生产构建与预览：

```bash
npm run build
npm run preview
```

构建结果位于 `dist/`，可由普通静态 HTTP 服务提供。不要直接双击 `dist/index.html`，浏览器对本地文件的模块加载有限制。依赖安装需要网络，游戏运行和计算均在本地；没有外部图片、字体、AI 或业务接口请求。

## GitHub Pages 发布

项目已包含 `.github/workflows/pages.yml`。将代码推送至目标仓库的 `main`，并在仓库的 Settings → Pages 中将发布来源设为 GitHub Actions；后续涉及代码或配置的推送会自动运行核心测试、生产构建与静态站点发布，也可从 Actions 手动触发。仅修改 Markdown 文档时跳过重复发布。

工作流通过 GitHub 官方动作读取站点的实际子目录，并设置 `VITE_BASE_PATH`。本地默认仍使用 `/`；自行复现子目录构建时可执行：

```bash
VITE_BASE_PATH=/EV-Era/ npm run build
VITE_BASE_PATH=/EV-Era/ npm run preview
```

站点文件只有浏览器前端，不需要配置 API 密钥或业务服务器。存档仍保存在访问者自己的浏览器中；本地地址与线上域名的存储空间不同，需要通过存档中心导出、导入来迁移已有进度。

## 首局玩法

1. 在「车型与技术研发」确认产品配置，选择标准研发、增配团队、成熟平台、聚焦核心或压缩验证并立项。
2. 在「配置经营计划」设定季度研发、营销、质量预算与生产目标。额度按 13 周执行，修改从下一周生效。
3. 单周推进，或以 1× / 6× 速度自动运营。快速按钮推进到季末；重大事件会提前暂停。
4. 研发完成后批准上市，或保留 CTO 自主授权，由其根据目标和验证状态安排上市。
5. 订单产生后，团队根据需求、产能、库存与现金采购生产；实际交付才会确认收入。
6. 结合季度报告调整价格、预算、供应商、产能或融资，持续经营 12 季度。

未亲自操作时，CTO 可以自主立项与上市，CFO 可以使用有限授信，运营高管可以调查和召回。关闭自主授权仍会保留普通部门工作，但重大决策需由 CEO 处理。

## 主要规则

### 市场不是营销倍率

六类消费者分别评估价格、续航、性能、辅助驾驶、座舱、安全、品牌和等待时间。所有企业与「暂不购买」竞争同一份潜在需求，营销影响使用对数函数，边际收益递减。

潜在需求、新增订单、退订、实际交付与累计保有量分别保存。界面的市场份额是本局虚构细分市场的实际交付份额；尚未上市时的画像和定价试算只是预测，不会生成订单。

### 利润和现金分开核算

引擎金额统一为**百万元**，包括售价；界面换算为万元、亿元。

- 采购生产：减少现金，形成库存，尚不减少汽车毛利润。
- 实际交付：收到售价对应现金，并按原批次成本结转销售成本。
- 研发、营销、质量、薪酬、固定费用、利息和售后：同时影响现金与利润。
- 建厂和扩产：资本支出，影响现金；后续新增固定经营费用。MVP 暂未单列资产折旧。
- 贷款、还款和股权融资：影响现金、负债或持股，不算营业收入。

银行总授信 10 亿元，基础年利率 6.5%；股权融资按当前估值稀释，每轮间隔 13 周。估值考虑收入、增长、盈利、技术、品牌、现金、债务及未处理质量风险，不能直接用于支付费用。现金耗尽且有限授信无法弥补时破产。

### 质量是历史决策的后果

生产时冻结该批次的验证度、供应商、质量预算、产量爬坡及潜在缺陷率。耐久风险按车辆**实际交付后的使用时间**暴露，不把库存时间当作车主车龄。潜在缺陷数值不直接显示给 CEO，调查后才展示可确认的原因与关联批次。

成熟平台、增加团队和精简功能可以提速，均不等同于减少质量验证。压缩验证、低可靠供应商和不足的检测投入会增加潜在风险。正常的零星投诉不会自动变成批次级事故。

严重事件需要调查、报告和修复；长期忽略将增加声誉损失、成本与强制暂停交付。召回支出覆盖维修与车主补偿，并改善后续供应链和验证；历史事件仍然保留。公开沟通只能影响传播，不能消除真实缺陷。监管机制和数值均为游戏抽象。

### 注意力用于额外管理

每季度有三个管理月，在季度第 1、5、9 周刷新为 10 点，不结转剩余点数。浏览、定价、季度战略、授权与普通融资不消耗注意力。

| 专项     | 消耗           | 真实效果                        |
| -------- | -------------- | ------------------------------- |
| 研发审查 | 2 点           | 验证度增加 8，未来 4 周研发加速 |
| 生产协调 | 2 点           | 未来 4 周可用产能提高 12%       |
| 财务审计 | 2 点           | 13 周内年利率下降 0.8 个百分点  |
| 质量调查 | 3 点及检测资金 | 确认历史原因、证据和关联批次    |
| 协调召回 | 2 点及维修资金 | 修复受影响车辆，整改后续生产    |
| 公开沟通 | 2 点及沟通费用 | 解释事实、影响传播，不修复缺陷  |
| 补充报告 | 1 点           | 根据实时业务数据生成专项说明    |

保留高管自主授权可让团队完成调查和召回，不占用 CEO 注意力。暂缓部门建议会暂停该部门 4 周内自主发起重大决策，普通执行继续，安全义务不被豁免。

## 存档与复盘

- 自动进度保存在当前浏览器、当前站点的 `localStorage`；端口变化也会形成不同存储空间。
- 项目更名保留原存档键和文件格式，继续兼容 GameX 时期的自动进度、手动快照、导出文件与本地排行；同一浏览器访问同一域名时，仅更换站点子路径不会隔离 `localStorage`。
- 手动快照独立于自动存档。读取会替换当前进度，重要分支建议先导出 JSON 文件。
- 存档保留种子生成器的内部状态、历史批次、全部决策、财务流水和季度报告；导入校验失败不覆盖当前进度。
- 「企业历史与复盘 → 校验种子复盘」从原始开局重新执行全部重大决策，并对经营事实与流水生成校验码。消息阅读状态、暂停提示不影响经营事实。
- 本地排行榜保留结算企业，支持按估值、利润、交付、份额、技术、声誉或存续时间排序，不使用单一胜利分数。

## 验证与平衡

```bash
npm test           # 核心纯函数、财务对账和真实策略情景
npm run test:e2e   # 使用本机已安装的 Google Chrome 验收真实交互
npm run simulate   # 五种战略 × 十个种子，每局 156 周
npm run build      # TypeScript 检查及生产打包
npm run format     # 整理源码与文档格式
```

浏览器测试可以自动启动本地开发服务，也会复用已运行的 5173 端口。验收报告、失败追踪、截图与策略观测结果生成在 `.local/qa/`，不进入 Git。

核心测试覆盖：研发持续投入、低价规模、稳健质量、不同提速方式、价格战、忽略质量预警、召回整改、现金枯竭、无人干预、注意力专项、种子复现、存档后继续模拟、实际交付车龄及现金/利润/库存对账。测试断言真实数值与状态。

五种默认路线的多种子观测用于发现明显参数问题，不代表已证明长期平衡或排除了所有最优策略。玩家口碑、难度曲线和更广的策略搜索仍需要后续人工试玩。

## 工程结构

```text
src/engine/        数据模型、配置、指令、周度模拟、市场、质量与复盘
src/ui/            六个管理模块、图表、车辆视觉组件与开局界面
src/assets/vehicles/ 高分辨率透明底车辆产品渲染
src/App.tsx        应用状态、时间控制、业务导航和对话框
src/persistence.ts 版本化存档、校验与本地多维排行
scripts/balance.ts 多种子策略观测
tests/game.spec.ts 浏览器完整游玩、危机和小屏验收
.agentdocs/        需求入口、当前结论和阶段验证记录
```

引擎不依赖 React、真实时间或网络，外部状态变更经 `applyCommand`，周度推进经 `advanceWeek`。所有随机性经 `randomStep`，关键经济参数集中于 `src/engine/config.ts`。
